## 0. 全貌（一句话）

> 本项目在 SFT 基础上，**冻结底座只训 LoRA**，并在**输入 embedding 空间**做 **K 步 PGD 对抗训练**；关键创新是**用 CE 与对抗损失的梯度范数比 γ 经 tanh 动态调节扰动半径 ε**，让对抗强度随训练自适应。

```text
input_ids -> 冻结的 embedding E
                    |
      +-------------+-------------+
      |                           |
   E（干净）                    E + δ（对抗, PGD生成）
      |                           |
   CE loss & 梯度              Adv loss & 梯度
      |                           |
      +---- 手动累加到 p.grad ----+
                    |
        (仅更新 LoRA 参数)
```

## 0.1 对哪个模型微调、为什么、占用多少资源

**项目配置的底座**：`Qwen/Qwen2.5-0.5B-Instruct`。

**为什么选它**：
1. **中文能力强**：Qwen 系列中文语料充分，适合中文领域任务。
2. **小**：0.5B 参数，普通单卡就能训，适合科研快速验证与迭代。
3. **Instruct 版本**：自带对话模板，天然适合 SFT。
4. **开源可本地部署**：数据不出内网，合规友好。
5. **生态成熟**：transformers / peft 支持好，坑少。

**资源占用（量级）**：
- 0.5B + LoRA + bf16、`batch=1`、`max_length=3072`，单卡显存通常只需**几 GB**。
- 参考复现：单卡 NVIDIA H20，Qwen3-1.7B + LoRA（8.72M 可训练参数）、`batch1×累积8`、`max_length=2048`、270 步，约 **10GB 显存、22 分钟**；0.5B 更省更快。

> 面试口径：项目配置是 Qwen2.5-0.5B；复现/验证用的是环境里可用的 Qwen3-1.7B。**显存与时长要如实说**，建议现场实测，不要编数字。

# 第 1 部分：LoRA 原理

## 1.1 全参微调的问题

对一个权重矩阵：

```text
W 形状: (d_out, d_in)
```

全参微调直接更新 W。问题：
- 参数量大（大模型动辄几十上百亿）；
- 优化器状态（Adam 的 m、v）是参数量的 2 倍；
- 显存、保存、部署成本都高。

## 1.2 LoRA 核心公式

冻结 W，只学一个**低秩增量**：

```text
ΔW = B · A

A 形状: (r, d_in)
B 形状: (d_out, r)
r << min(d_in, d_out)
```

前向：

```text
y = W·x + (alpha / r) · B · A · x
```

- 初始化：A 用高斯/均匀随机，**B 初始化为 0** → 训练开始时 `ΔW = 0`，模型与底座完全一致，训练稳定。
- `alpha / r` 是缩放系数（scaling）。

### 1.2.1 名字含义 & 为什么“低秩”可行

- **LoRA = Low-Rank Adaptation，低秩适配**。
- “低秩”指：增量 `ΔW = B·A` 的**秩最多是 r**（两个窄矩阵的乘积），而 `r` 很小（本项目 r=8）。
- 为什么可行：微调对权重矩阵的改变，其“信息量”通常远小于原始矩阵，用低秩就能近似，于是**用极少参数逼近全参微调**。
- 一句话：**不重写整张权重表，只加一个很小的“修正项”。**

## 1.3 为什么省显存 / 参数

可训练参数量从 `d_out × d_in` 降为：

```text
r × (d_in + d_out)
```

以本项目 Qwen2.5-0.5B（24 层，hidden=896，GQA）粗略估算，注入 7 个投影后 LoRA 参数只有**数百万量级（不到全模型 1%）**。

显存节省来自：只保存少量 LoRA 参数的梯度与优化器状态，底座权重冻结不动。

## 1.4 项目 LoRA 配置

```yaml
r: 8
lora_alpha: 16
dropout: 0.05
target_modules: [q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj]
```

- `r=8`：低秩容量，折中。
- `alpha=16`：`alpha/r = 2`，适度缩放。
- `dropout=0.05`：只作用于 LoRA 分支，防小数据过拟合。
- 覆盖注意力（q/k/v/o）+ MLP（gate/up/down）。

## 1.5 注入在模型哪里（是不是每层都加？）

**是——在每个 Transformer Block 里的这 7 个线性层都加，但不是模型的“所有层”。**

```text
Transformer 结构（block 重复 N 次）：
  [embed_tokens 词嵌入]                       -> 不加 LoRA
  Block × N:
      Attention: q_proj k_proj v_proj o_proj  -> 每个 block 都加 LoRA
      MLP:       gate_proj up_proj down_proj   -> 每个 block 都加 LoRA
  [norm 归一化]                               -> 不加 LoRA
  [lm_head 输出头]                            -> 不加 LoRA
```

- Attention 的 q/k/v/o：决定“关注什么信息”。
- MLP 的 gate/up/down：决定“如何变换信息”。
- **不训**：`embed_tokens`、`norm`、`lm_head`（参数量大且与任务关系小）。

推理时可 **merge**：`W' = W + (alpha/r)·BA`，合并后无额外推理延迟。

> 面试问“LoRA 加在哪”：答“注意力和 MLP 的投影层，每个 block 都加；embedding、norm、输出头不加”。是否每层都加由 `target_modules` 决定，也可以只加 q/v 进一步省参数。

## 1.6 每个参数是什么意思、怎么设置

| 参数 | 含义 | 调大 | 调小 | 常用值 |
|---|---|---|---|---|
| `r` | 低秩矩阵的中间维度（秩），决定“能学多复杂的修正” | 容量↑、参数↑、易过拟合、显存↑ | 容量↓、可能欠拟合 | 8 / 16 / 32 / 64；本项目 8 |
| `alpha` | 缩放系数，实际缩放 = `alpha/r` | 更新幅度↑、更激进 | 更新幅度↓、更保守 | 常设 `r` 或 `2r`；本项目 16 |
| `dropout` | 只作用于 LoRA 分支的随机丢弃 | 正则↑、更不易过拟合 | 拟合↑、可能过拟合 | 0 ~ 0.1；本项目 0.05 |
| `target_modules` | 在哪些层加 LoRA | 层多→容量↑、显存↑ | 层少→容量↓ | 先 q/v，再 q/k/v/o + MLP；本项目 7 个 |
| 学习率 | 每步走多大 | 收敛快、易不稳 | 收敛慢 | LoRA 常 1e-4 ~ 2e-4；本项目 1e-5（保守） |

**怎么选（经验）**：
- `r`：先 8，欠拟合再升 16/32；越大不是越好，会更容易过拟合。
- `alpha`：保持 `alpha/r = 1~2` 比较稳（本项目 16/8=2）。
- `dropout`：小数据容易过拟合就加 0.05~0.1。
- `target_modules`：默认注意力 q/v 起步；本任务要学结构化长输出，加到 q/k/v/o + MLP。
- 学习率：LoRA 通常比全参大一个量级（1e-4 级），本项目用了更稳的 1e-5。

> 面试口径：**参数不是拍脑袋定的**，先取社区常用默认值，再用留出验证集做单变量消融（r、target_modules、lr 分别试）。

## 1.7 PEFT 家族与其他方法（各自改哪儿？）

**PEFT 是一大类“只改一点点”的方法，LoRA 是其中最主流的一种。**

| 方法 | 改什么 / 怎么改 | 直觉 | 推理开销 |
|---|---|---|---|
| **LoRA** | 在权重旁学低秩增量 `ΔW = B·A` | 只加一个小修正项 | 可 merge，零延迟 |
| QLoRA | 底座先 4bit 量化，再套 LoRA | 更省显存，精度略降 | 可 merge |
| Adapter | 层与层之间插小“瓶颈”MLP（降维→升维） | 加了个小补丁模块 | 增加层，有延迟 |
| Prefix-Tuning | 在每层 attention 的 K/V 前拼一段可学习“虚拟前缀” | 给每层加提示向量 | 占序列长度 |
| P-Tuning / Prompt Tuning | 只学输入端（或各层前）的“软 prompt”向量 | 不改权重，只调提示 | 占序列长度 |
| BitFit | 只训练所有 bias 参数 | 只动偏置 | 无 |
| IA3 | 学对激活做逐元素缩放的向量 | 用向量缩放激活 | 无 |

**为什么本项目选 LoRA（4 条）**：
1. **省**：可训练参数不到 1%，单卡可训，存储小；
2. **快且无推理延迟**：可 merge 进 `W`，推理与底座一致；
3. **稳**：底座冻结，小数据下过拟合/遗忘更少；
4. **成熟**：`peft` 库直接支持，社区实践多、坑少。

> 面试高频：**LoRA / QLoRA / PEFT 几乎是必考**。要能说清“低秩是什么、加在哪、为什么省、怎么 merge、和 Adapter/Prefix/BitFit 的区别”。

# 第 2 部分：对抗训练原理

## 2.0 关键澄清：对抗训练里“谁攻击谁、对谁对抗”？

这是最容易混的点。对抗训练里有**两个角色**：

| 角色 | 对象 | 是模型参数吗 | 生命周期 |
|---|---|---|---|
| **攻击方** | 输入表示 **δ**（加在 embedding 上） | **不是**，是临时张量 | 每个 step 现场生成，用完即弃 |
| **防守方** | **模型权重**（本项目的 LoRA A/B） | 是 | 被持续训练、保存 |

**所以“对哪个参数对抗”的答案**：
- **对抗（攻击）的是输入**——在 embedding 上加一个最坏的小扰动 δ；
- **被训练的是模型权重**——让模型在“被攻击的输入”上也要答对；
- **δ 本身不是模型参数**，不保存，只是一个临时的“刁难”。

**类比**：δ 是临时找来的“陪练”，学生（模型参数）靠应对刁难而变强；陪练用完就走，不属于学生。

> 对比：**AWP** 才是“攻击权重”（扰的是模型参数）；本项目 **PGD-AT 攻击的是输入**，两者完全不同。

## 2.1 为什么要对抗训练

本项目输入存在不确定性：
- 企业描述同义改写；
- 字段缺失或检索到的成果略有偏差；
- 表达顺序变化。

若只拟合干净样本，输入轻微变化时输出可能不稳。对抗训练在**最坏方向**加受限扰动，要求模型在邻域内也保持正确——提升鲁棒性与泛化。

### 直觉类比

> 训练学生做题时，不只给标准题，还故意把题目**轻微改写、加一点噪音**（标准答案不变），逼学生**抓本质、别死记**。对抗训练就是“主动制造最刁钻的小改动”。

- **为什么是“最坏方向”**：随机加噪是随机的；对抗训练专门找“最容易让模型出错的那一点小改动”，更有针对性。
- **为什么要限制幅度**：改动必须“小”（`|δ| ≤ ε`），否则语义都变了，就变成另一道题了。

### 为什么选这个方法（而不是别的正则）

1. 项目输入天生有噪声（检索匹配偏差、同义改写），对抗训练正好针对“输入鲁棒性”。
2. **embedding 空间 PGD** 实现直接、可控，能与 LoRA 训练放在同一循环里完成。
3. 相比 R-Drop（靠 dropout 一致性）、AWP（扰权重），本方法扰动的是**输入表示**，更贴近真实输入噪声。
4. 动态 ε 让扰动强度自适应，缓解“固定扰动要么太弱要么破坏训练”的问题。

## 2.2 为什么扰动加在 embedding 空间

token 是离散的，无法直接梯度上升；embedding 是**连续可微**向量，可沿梯度找最坏扰动。

```text
E_adv = E + δ
约束:  |δ|_2 <= ε        # 扰动的 L2 范数不超过 ε
```

> **重要澄清**：扰动加在 embedding 的**输出表示**上，**不等于**训练 embedding 层的权重。本项目 embedding 权重是**冻结**的，真正被训练的是 LoRA 参数。“在 embedding 上加扰动”和“微调 embedding 层”是两件完全不同的事。

## 2.3 PGD 是什么？和 FGSM 区别？

**PGD = Projected Gradient Descent（投影梯度下降）**，这里指一种**对抗攻击方法**：在允许范围内，找“让 loss 最大的那个最坏扰动”。

**名字三步拆解**：
- **Gradient（梯度）**：用 loss 对 δ 的梯度，判断“往哪个方向改会让模型更错”。
- **Descent（下降）**：名字沿用优化框架；这里是**把 loss 往上推（最大化）**，即攻击。
- **Projected（投影）**：每走一步后，若 δ 超出允许范围（`|δ| > ε`），就把它**缩放回范围内**。

**迭代过程**（K 步）：

```text
初始 δ（随机）
重复 K 次:
   沿“让 loss 变大”的方向走一小步
   若超出 |δ| ≤ ε，就投影回球内
```

**和 FGSM 对比**：

```text
FGSM: 只走一大步               （快、便宜、弱）
PGD : 走 K 个小步、每步都投影   （慢、贵、强；本项目 K=3）
```

**直觉**：FGSM 像“随便改一下”就交卷；PGD 像“反复微调，专门找最能让你答错的那版改写”。

> 注意：这里的 PGD 与优化器里的“投影梯度下降”同源，但用途是**造对抗样本**，不是更新模型参数。

## 2.4 PGD 生成扰动（本项目）

**随机初始化**（比零初始化探索性更好）：

```text
δ_0 ~ Uniform(-ε, ε)         # 每维均匀随机
```

**K 步迭代**（每一步）：

```text
1) 前向:  L_adv = loss(model, E + δ)
2) 记录 loss 最大的 δ
3) 梯度:  g = ∇_δ L_adv
4) 按样本归一化: g_dir = g / |g|_2      (每个样本单位方向)
5) 更新:  δ = δ + α · g_dir
6) 投影:  把 δ 缩放回 |δ|_2 <= ε
```

> 注意本项目用的是**按样本归一化的梯度方向 × α**，不是原始 PGD 的 sign 或未归一化梯度。即每步走的长度由 `α` 控制。

**L2 投影 `project_onto_l2_ball`**：把每个样本的 δ 展平算 L2 范数，若超过 ε 就乘 `ε/norm` 缩小。

## 2.5 为什么保留 loss 最大的 δ

PGD 最后一步不一定 loss 最大。记录整个 K 步中 loss 最大的 δ，用它算最终对抗梯度，更接近“局部最坏样本”。

# 第 3 部分：动态对抗训练（本项目的创新）

## 3.1 ε 是什么？固定 ε 有什么问题？

**ε（epsilon）= 允许的扰动最大幅度**，也就是“陪练难度”：
- ε 越大 → 扰动越强 → 模型被逼得越狠；
- ε 越小 → 扰动越弱 → 几乎没锻炼效果。

固定 ε 的问题：
- ε 太小：几乎没正则效果，鲁棒性没提升。
- ε 太大：早期训练被破坏、后期过度干扰。
- 训练不同阶段对扰动的承受力不同，**固定 ε 不适应**。

**直觉类比**：给学生配陪练，一开始就上“地狱难度”，学生会崩、学不进去；一直是“幼儿园难度”，又练不出水平。**难度应该随水平动态调整。**

**动态 ε 就是干这个**：让扰动强度随训练进程自适应（下一节 3.3 给公式）。

## 3.2 梯度范数比 γ

用上一步的两路梯度范数比：

```text
gamma_t = |g_ce^{t-1}|_2 / ( |g_adv^{t-1}|_2 + eta )     # eta 是极小量，防除零
```

直觉：
- CE 梯度相对大 → 标准任务仍主导 → 可以**加大**扰动。
- Adv 梯度相对大 → 对抗目标已很强 → 应**抑制**扰动。

## 3.3 ε 的更新（核心）

```text
warmup 阶段 (step < T_warmup):
    ε_t = ε_max * ( step / T_warmup )        # 从 0 线性升到 ε_max

warmup 之后:
    ε_t = ε_max * tanh( gamma_t )            # 由梯度比自适应

最后裁剪: ε_t = clamp(ε_t, 1e-6, ε_max)
```

- `tanh` 把比值平滑压到 (0,1)，保证 ε 不超过上限、避免异常放大。
- 项目值：`ε_max=0.4`、`T_warmup=0.15×总步数`、`α=0.05`、`K=3`、`lambda_adv=1.0`。

> **一句话创新点**：扰动半径不是常数，而是由“标准损失/对抗损失梯度范数比”经 `tanh` 动态决定——早期 warmup 温和起步，后期按需要自适应。

## 3.4 为什么不用 `loss = ce + λ·adv` 直接 backward

因为 γ 需要**分别**拿到 CE 梯度和 Adv 梯度的范数。所以：

```python
ce_grads  = torch.autograd.grad(ce_loss,  trainable)
adv_grads = torch.autograd.grad(adv_loss, trainable)
```

再手动累加到 `p.grad`：

```text
p.grad += (1/A) * g_ce + (lambda_adv / A) * g_adv     # A = 梯度累积步数
```

这样能：分别监控两路梯度、实现 ε 自适应、精确控制累积。

## 3.5 梯度累积（配合手写梯度）

- 真实 batch = micro_batch × A（项目 1 × 8）。
- 每个 micro-batch 把梯度按 `1/A`、`lambda_adv/A` 累加。
- 满 A 步后：梯度裁剪 → `optimizer.step()` → `scheduler.step()` → 清零。
- 用到的范数存下来，供**下一个** step 计算 γ（避免循环依赖）。

## 3.6 `detach` 的作用

- `embeds.detach()`：不更新词嵌入，只让 LoRA 参与优化。
- `g.detach()`：只保留梯度数值，不建高阶图。
- `delta.detach()`：每次 PGD 更新后切断旧图，防止 K 步图无限增长。

## 3.7 已知的近似（诚实点）

1. **梯度范数是近似**：用各 micro-batch 范数平方和开根号 `sqrt(Σ|g_i|²)`，不等于“先求和再取范数”的 `|Σ g_i|`（忽略交叉项）。应表述为“梯度敏感度近似”。
2. **日志 loss 是最后一个 micro-batch**：不是累积窗口平均，曲线会抖。

## 3.8 对抗超参怎么调

| 参数 | 含义 | 调大 | 调小 |
|---|---|---|---|
| `eps_max` | 扰动半径上限（扰动强度） | 对抗更强、易破坏收敛 | 更温和、可能无效 |
| `adv_alpha` | PGD 单步步长 | 更快到位、易过冲 | 更精细、需要更多步 |
| `K`（`steps`） | PGD 步数 | 攻击更强、成本 ×K | 更省、更弱 |
| `lambda_adv` | 对抗损失权重 | 更强调鲁棒、可能压过主任务 | 更偏主任务 |
| `twarmup_frac` | ε 的 warmup 比例 | 更晚进入动态、更稳 | 更早对抗、可能不稳 |

项目值：`eps_max=0.4`、`adv_alpha=0.05`、`K=3`、`lambda_adv=1.0`、`twarmup_frac=0.15`。

**调优思路**：
- 训练不稳 / 主任务变差 → 降 `eps_max`、降 `lambda_adv`、增大 `twarmup_frac`。
- 对抗没效果 → 在稳定前提下增 `K` / `eps_max` / `lambda_adv`。
- **评估**：干净测试集 + 扰动测试集都要看（鲁棒性提升，且干净集不能明显下降）。
- **成本**：每步多 K 次前向+反传，约 (K+1) 倍开销。

---

## 3.9 一次对抗训练到底发生了什么（逐步走一遍）

假设某个 micro-batch，句子经 embedding 得到 `E`，`eps_t = 0.2`、`adv_alpha = 0.05`、`K = 3`：

```text
第 0 步  干净前向：得到 CE loss -> 取 g_ce（标准任务梯度）

第 1 步  随机初始化 delta ~ Uniform(-0.2, 0.2)，投影到 |delta| <= 0.2

         PGD 循环（重复 K=3 次）:
           ① 前向 E+delta -> adv_loss = 3.10（记录，当前最大）
              取梯度 g = ∇_delta adv_loss
              delta = delta + 0.05 * (g / |g|)     # 按样本归一化方向走一步
              投影回 |delta| <= 0.2
           ② 前向 -> adv_loss = 3.50（更大，记录）
              同样更新 + 投影
           ③ 前向 -> adv_loss = 3.30（不是最大）
              同样更新 + 投影
         取整个循环中 loss 最大的 delta（即第②步那个）

第 2 步  用 max_delta 前向 -> adv_loss_final -> 取 g_adv

第 3 步  合并到参数梯度：
           p.grad += (1/A) * g_ce + (lambda_adv / A) * g_adv

第 4 步  累积满 A 步后：梯度裁剪 -> AdamW.step() -> scheduler.step() -> 清零
```

**每一步在做什么**：
- 前向两次：一次干净（CE），一次对抗（Adv）。
- PGD 循环每步多一次前向+反传，K=3 → 总开销约 (K+1) 倍。
- `delta.detach()` 保证 K 步不累积计算图。
- 下一个 step 用本次存下的 `|g_ce|`、`|g_adv|` 算新的 γ → 新的 ε。

---

# 第 4 部分：训练完整流程

```text
1. input_ids -> 冻结 embedding E
2. 用上一步范数算 gamma_t、eps_t
3. 干净前向 -> CE loss -> 存 CE 梯度并累加
4. 随机初始化 delta，做 K 步 PGD，保留最大 loss 的 delta
5. 用最大 delta 前向 -> Adv loss -> 存 Adv 梯度并累加
6. 满 A 步：clip -> step -> scheduler -> zero_grad
7. 记录 loss/γ/ε；定期验证、按验证 loss 存 best
8. 结束保存 final
```

# 第 5 部分：与其他对抗/正则方法对比

| 方法 | 扰动对象 | 特点 |
|---|---|---|
| FGSM-AT | embedding | 单步，便宜，弱 |
| **PGD-AT（本项目攻击）** | embedding | 多步，强，贵 |
| FreeLB | embedding | 多次上升+一次下降，复用计算 |
| **AWP** | **权重** | 扰动模型参数，不是输入 |
| VAT | embedding | 朝最大化 **KL**（平滑性）方向扰动 |
| SMART | embedding | 平滑性正则化对抗 |
| R-Drop | dropout | 两次 dropout 输出一致，非对抗 |

本项目的差异化：**embedding 空间 PGD + 由梯度比动态调 ε**。

# 第 6 部分：实验结果与正确口径

**环境**：单卡 NVIDIA H20；底座替换为可用的 Qwen3-1.7B（隔离环境无原配置的 Qwen2.5-0.5B）；任务同构种子数据；测试行业不出现在训练集。

| 指标 | Base | LoRA + 动态对抗 |
|---|---:|---:|
| PPL ↓ | 16.72 | **14.65** |
| BLEU-4 ↑ | 0.18 | **28.36** |
| 含【方向一】 | 11.7% | **100%** |
| 含【战略价值】/【技术路线】 | 0% | **100% / 100%** |

**训练过程**：CE loss ≈ 2.60 → 0.02；Adv loss ≈ 2.60 → 0.03；ε warmup 后稳定在约 0.19~0.29；270 步、约 22 分钟；LoRA 可训练参数约 8.72M（Qwen3-1.7B，约 0.51%）。

**诚实口径**：
- 这是同构种子数据上的链路验证，不是真实线上数据。
- base vs post 同时含 SFT 和对抗两个变化，**不能单独证明对抗训练的增益**；要补“纯 LoRA vs 固定 ε vs 动态 ε”消融。
- 不要把 BLEU/ROUGE 叫“准确率”。

# 第 7 部分：遇到的问题与解决

| 问题 | 现象 | 解决 |
|---|---|---|
| LoRA dtype 不匹配 | bf16 输入 vs fp32 参数报 `dtype` 错 | forward 里 `lora_A.to(x.dtype)` |
| 显存增长 | K 步 PGD 计算图累积 | 每步 `delta.detach()`；及时 `del` 中间张量 |
| γ 不稳定使 ε 抖动 | ε 忽大忽小 | warmup + `tanh` 限幅 + clamp |
| 梯度范数近似 | 与真实累计范数有偏差 | 表述清楚；可改为对 `p.grad` 算真实范数 |
| loss 曲线抖 | 记录的是最后 micro-batch | 累加求平均 |
| 与 SFT 干扰 | 对抗过强破坏收敛 | `lambda_adv` 调节、动态 ε、warmup |
| 版本兼容 | transformers 不认新架构 / jinja2 太旧 | 换匹配版本 / 手写模板 |

# 第 8 部分：面试题（详解版）

> 每题写法：**面试官想听什么 → 分层回答 → 可能追问**。

## A. LoRA / PEFT

**Q1：LoRA 原理？**
- 想听：是否理解“低秩增量”的本质。
- 答：
  1. 冻结预训练权重 W，只学低秩增量 `ΔW = B·A`（A 是 `r×d_in`，B 是 `d_out×r`，r 很小）；
  2. 前向 `y = Wx + (α/r)·B·A·x`；
  3. B 初始化为 0 → 训练开始 `ΔW=0`，起点等价底座；
  4. `ΔW` 的秩 ≤ r，用极少参数逼近全参微调。
- 追问“为什么低秩够用”→ 微调对权重的改变信息量远小于原矩阵。

**Q2：LoRA 为什么省显存 / 省存储？**
- 只保存 LoRA 参数的梯度与优化器状态；底座冻结，不存底座梯度。每任务只存一个小适配器。

**Q3：LoRA 加在哪些层？**
- 本项目：每个 Transformer block 的 attention（q/k/v/o）+ MLP（gate/up/down）；不加 embed_tokens、norm、lm_head。
- 追问“能只加 q/v 吗”→ 可以，更省但容量小，要消融。

**Q4：r / alpha / dropout / target_modules 怎么选？**
- 先取默认（r=8、alpha=2r、dropout≈0.05、目标层从 q/v 起步），再单变量消融。
- r↑容量↑易过拟合；alpha/r 控制在 1~2；dropout 防小数据过拟合；target 越多容量越大越贵。

**Q5：LoRA 和其他 PEFT / 全参的区别？**
- 全参：所有参数；LoRA：低秩增量；Adapter：插小模块；Prefix/P-Tuning：学虚拟前缀/软 prompt；BitFit：只训 bias；QLoRA：4bit 量化底座 + LoRA。

**Q6：LoRA 推理会变慢吗？**
- 不会。可 merge：`W' = W + (α/r)BA`，结构与底座一致，零额外延迟。

## B. 对抗训练

**Q7：什么是对抗训练？为什么做？**
- 在输入上加“最坏的小扰动”，要求模型在这种输入下也答对 → 提升鲁棒性/泛化。
- 直觉：故意把题轻微改写加噪（答案不变），逼模型抓本质、别死记。

**Q8：PGD 是什么？和 FGSM 区别？**
- PGD = Projected Gradient Descent（投影梯度下降）。对抗攻击做法：在 `|δ|≤ε` 内，迭代地沿“让 loss 变大”的方向走小步，每步后把 δ **投影**回约束球（超出就缩回）。
- FGSM：单步（快、弱）；PGD：多步（慢、强）。本项目 K=3。
- 追问“为什么叫 descent”→ 名字来自优化框架；这里是对 loss 做**最大化**（上升），用投影梯度法求解。

**Q9：为什么扰动加在 embedding，不是 token？**
- token 离散不可导；embedding 连续可微，能求梯度找最坏扰动。
- **重要澄清**：扰动加在 embedding 的**输出**上，不等于训练 embedding 权重；embedding 权重是**冻结**的，被训练的是 LoRA 参数。

**Q10：为什么 δ 随机初始化而不是 0？**
- 零初始化可能限制首步方向、易退化；随机初始化增加探索。

**Q11：ε（扰动幅度）怎么理解？**
- ε 是“陪练难度”：太大破坏训练，太小没效果。本项目 `ε_max=0.4`。

**Q12：动态 ε 是什么？有什么用？**
- 固定 ε 不适应阶段：早期模型弱，太强扰动能毁训练；后期模型强，太弱没锻炼效果。
- 动态：warmup 从 0 线性升到 ε_max；之后 `ε_t = ε_max · tanh(γ_t)`。
- `γ_t = |g_ce| / |g_adv|`：CE 梯度大（主任务还在学）→ 加大扰动；对抗梯度已强 → 抑制。
- `tanh` 平滑限幅，保证 ε 在 (0, ε_max)。
- 一句话：**对抗强度随训练自适应，既不过早打击、也不后期无效。**

**Q13：为什么不直接 `ce + λ·adv` 反传？**
- 需要分别拿到 CE 与对抗梯度的范数来算 γ，并精确控制梯度累积比例。

**Q14：梯度范数是精确的吗？**
- 不是；是多 micro-batch 范数平方和开根号的近似，忽略交叉项。

**Q15：和 AWP / FreeLB / R-Drop 区别？**
- AWP 扰权重（不是输入）；FreeLB 复用前向的免费对抗；R-Drop 靠 dropout 一致性，不是对抗。

**Q16：对抗训练成本增加多少？**
- 每步多 K 次前向+反传，约 (K+1) 倍。

**Q17：怎么证明对抗训练有效？**
- 消融：纯 LoRA / 固定 ε / 动态 ε；在干净集 + 扰动集上同时评估。

**Q18：对抗超参怎么调？**
- 不稳：降 eps_max / lambda_adv、增 twarmup；想更强：增 K / eps_max；干净集不能明显掉。

## C. 训练与工程

**Q19：对哪个模型微调，为什么？**
- Qwen2.5-0.5B-Instruct：中文强、参数小单卡可训、Instruct 自带对话模板、开源可本地部署、生态成熟。

**Q20：占多少显存、训多久？**
- 0.5B + LoRA + bf16 单卡通常几 GB；复现 1.7B 约 10GB、22 分钟。**如实测**，不要编。

**Q21：为什么不用 RAG？RAG 是不是更好？**
- 项目前置的「企业↔专家/成果匹配」就是检索（检索增强输入 + SFT）。RAG 管知识、SFT 管行为，二者互补。

**Q22：BLEU-4 等指标是什么？用哪个数据集评估？**
- BLEU-4：生成与参考在 4-gram 上的重合度，越高越像（字面），但不是正确率。
- 数据集：SFT 流程切分出的测试集（`sample_sft_test.json`）；复现实验用同构种子数据的留出测试集。

**Q23：训练/推理不一致怎么排查？**
- 查 ChatML 模板、prompt 拼接是否一致；本项目就有训练 `\n` vs 评测 `\n\n输入：\n` 的技术债。
