## 0. 一句话理解

> 把两段文本各自变成一串数字（向量），再算这两个向量的“夹角”。夹角越小越像。
> 项目用了**两种**把文本变数字的方法（句向量模型、TF-IDF），最后按 **0.8 : 0.2** 加权。

## 1. 先说人话：为什么要把文本变成数字

计算机不能直接比较“工业视觉检测”和“图像识别”像不像。所以：

```text
一段文本  ->  一个向量（一串数字）  ->  两个向量算相似度
```

本项目用了两种不同的“变数字”方式：

| 方式 | 结果 | 擅长什么 |
|---|---|---|
| 句向量模型（SentenceTransformer） | 一串稠密小数，如 768 个数 | 意思相近就相近（同义改写） |
| TF-IDF | 一大串 0，少数位置有权重 | 具体术语精确命中 |

## 2. 切词：是不是 jieba？要不要入数据库？

### 2.1 是 jieba

英文按空格切词，中文没有空格，所以需要**分词（切词）**。项目用的是 **jieba**，具体是带词性标注的 `jieba.posseg`。

```python
import jieba.posseg as pseg

for word, flag in pseg.cut("工业视觉检测与机器人控制"):
    print(word, flag)
# 工业 n
# 视觉 n
# 检测 v
# 与 c
# 机器人 n
# 控制 v
```

`flag` 是词性：`n` 名词、`v` 动词、`c` 连词……

### 2.2 项目怎么过滤词

项目写了一个自定义切词函数，交给 sklearn 的 TF-IDF 用：

```python
BLACKLIST = {"的", "和", "技术", "服务", "平台", "系统", "管理", ...}

def tokenize(text):
    words = []
    for w, flag in pseg.cut(text):
        if not w.strip():
            continue
        if w in BLACKLIST:          # 去掉无区分度的通用词
            continue
        if len(w) == 1:             # 去掉单字
            continue
        if flag.startswith("n") or flag.startswith("v") or flag == "eng":
            words.append(w)         # 只留名词/动词/英文数字词
    return words
```

规则总结：
- 用 **jieba** 切词；
- 只保留**名词、动词、英文数字词**；
- 去掉**停用词**（“的、和、技术、系统、平台……”）；
- 去掉**单字词**（单字区分度太低）。

### 2.3 需要入数据库吗？用什么数据库？

**不需要。当前项目没有使用任何数据库。**

数据流向是这样的：

```text
Excel 文件  --pandas读入-->  内存 DataFrame
                |
                +-- 切词 / TF-IDF --> sklearn 在内存里算
                |
                +-- 句向量        --> torch 在 GPU/内存里算
                |
                +-- 候选向量缓存  --> 存成 .npy 文件（普通文件，不是数据库）
```

- jieba **自带词典**，开箱即用，不需要额外接入词表数据库。
- 向量缓存是 `.npy` 文件（`model_cache/xxx_embeddings.npy`），只是“算过就不用重算”的缓存。
- 如果数据规模很大、要在线检索，才会考虑引入数据库/向量库，例如：
  - 原始业务数据：MySQL / PostgreSQL；
  - 向量检索：FAISS / Milvus / pgvector。

> **面试口径**：本项目用 Excel/JSONL + `.npy` 缓存，没有引入数据库；这是中小规模下的简化选择。规模变大后，会把原始数据放关系库、把候选向量放向量库，做 ANN 召回 + 精排。
> **不要说**自己在项目里用了 MySQL/Redis/向量数据库——代码里没有。

## 3. TF-IDF：先讲人话，再看公式

### 3.1 目标

给一句话里的每个词打一个“重要性分数”，重要的词权重高，没用的词权重低。这样两句话就能靠“有没有共同的重要词”来判断像不像。

### 3.2 两个直觉

- **TF（词频）**：一个词在这句话里出现越多，越能代表这句话。
- **IDF（逆文档频率）**：一个词在**很多句话里都出现**，说明它是废话（谁都有的词），重要性低；只在**很少几句话里出现**，说明它很“专属”，重要性高。

一句话记忆：**词频看局部，IDF 看全局；越稀有越重要。**

### 3.3 公式（纯文本）

```text
TF(t, d)  = 词 t 在文档 d 中出现的次数

IDF(t)    = ln( 文档总数 / 含词 t 的文档数 )
          = ln( N / df(t) )

TF-IDF    = TF(t, d) * IDF(t)
```

- `ln` 是自然对数。
- `df(t)` = 包含词 t 的文档数（document frequency）。
- 常见词 df 大 → IDF 小 → 权重被压低；稀有词 df 小 → IDF 大 → 权重被抬高。

### 3.4 项目实际用的 sklearn 版本

项目用 `sklearn` 的 `TfidfVectorizer`，它和教科书略有不同（**面试要讲准**）：

```text
sklearn 的 IDF = ln( (1 + N) / (1 + df(t)) ) + 1     # 平滑，避免除零/极端值
TF 默认        = 原始计数
最后一行        = L2 归一化（norm='l2'）
```

**因为最后做了 L2 归一化，所以两个文档的 TF-IDF 向量“点乘”就等于“余弦”。** 这就是项目里：

```python
score = expert_matrix @ query_vector   # 直接当余弦用
```

的原因。

### 3.5 手算一个迷你例子（照这个讲）

4 位专家，每位一句话（“文档”）：

```text
e1: 机器视觉  检测  缺陷
e2: 机器视觉  机器人  控制
e3: 机器视觉  检测  分类
e4: 机器视觉  质量  检测
```

**第一步：数 df（每个词出现在几篇文档里）**

| 词 | df | 说明 |
|---|---:|---|
| 机器视觉 | 4 | 4 篇都有 → 很通用 |
| 检测 | 3 | 3 篇有 |
| 缺陷 | 1 | 只 e1 有 → 很专属 |
| 机器人 | 1 | 只 e2 有 |
| 控制 | 1 | 只 e2 有 |
| 分类 | 1 | 只 e3 有 |
| 质量 | 1 | 只 e4 有 |

**第二步：算 IDF**（N = 4，用 sklearn 公式）

| 词 | 计算 | IDF |
|---|---|---:|
| 机器视觉 | ln(5/5)+1 | 1.000（最低，因为是通用词） |
| 检测 | ln(5/4)+1 | 1.223 |
| 缺陷/机器人/控制/分类/质量 | ln(5/2)+1 | 1.916（最高，因为稀有） |

> 看出来了：**“机器视觉”人人都提，权重最低；“缺陷”只有一家提，权重最高。**

**第三步：把企业 query 变成向量**

企业 query：`机器视觉 检测 缺陷`（每词 tf = 1）

```text
未归一化权重: 机器视觉 1.000, 检测 1.223, 缺陷 1.916
L2 长度 = sqrt(1.000^2 + 1.223^2 + 1.916^2) = 2.483
归一化后:     机器视觉 0.403, 检测 0.492, 缺陷 0.772
```

**第四步：和各位专家算“关键词相似度”（点乘 = 余弦）**

| 专家 | 归一化向量 | 与 query 点乘 |
|---|---|---:|
| e1（机器视觉 检测 缺陷） | 0.403, 0.492, 0.772 | 0.403²+0.492²+0.772² = **1.00** |
| e3（机器视觉 检测 分类） | 0.403, 0.492, 0.772(分类) | 只共享前两词 = **0.40** |
| e4（机器视觉 质量 检测） | 0.403, 0.772, 0.492 | 共享前两词 = **0.40** |
| e2（机器视觉 机器人 控制） | 0.346, 0.663, 0.663 | 只共享“机器视觉” = **0.14** |

结论：e1 关键词最像，e2 最不像。**这就是 TF-IDF 的判别力。**

> 项目细节：真实项目里 `min_df=2`，意思是“至少在 2 篇文档出现过的词才保留”，会过滤掉只出现一次的极稀有词。上面这个玩具例子为了讲清楚，用 min_df=1。

### 3.6 代码长什么样

```python
from sklearn.feature_extraction.text import TfidfVectorizer

# tokenize 就是 2.2 里那个 jieba 函数
vec = TfidfVectorizer(tokenizer=tokenize, min_df=2, ngram_range=(1, 1))

X = vec.fit_transform(expert_texts)      # 专家矩阵（每行一个专家）
q = vec.transform([enterprise_text])     # 企业向量

score = (X @ q.T).toarray().ravel()      # 点乘 = 余弦，得到每个专家的关键词分
```

`ngram_range=(1,1)` = 只用单个词，不做二元词组合。

## 4. 余弦相似度：人话 + 公式

### 4.1 人话

两个向量可以看作两支箭。**余弦看的是两支箭方向像不像，不看箭有多长。**

- 方向完全一样：cos = 1
- 垂直：cos = 0
- 方向相反：cos = -1

### 4.2 公式（纯文本）

```text
cos(a, b) = (a · b) / ( |a| * |b| )

其中:
  a · b = a1*b1 + a2*b2 + ... + an*bn        # 点积
  |a|   = sqrt(a1^2 + a2^2 + ... + an^2)     # 向量长度（L2 范数）
```

### 4.3 为什么不用欧氏距离

```text
长文本和短文本即使讲同一件事，向量长度也差很多。
欧氏距离会被“长度差”影响，判成不相似。
余弦先把长度除掉，只看方向，所以更适合文本。
```

### 4.4 两个工程细节

1. **先归一化再点乘。**
   如果两个向量都先变成长度 1（L2 归一化），那么 `cos = 点乘`。项目就是这么做的（`F.normalize` 后 `matmul`），省去每次算长度。

2. **把余弦从 [-1,1] 映射到 [0,1]（只在专家匹配里）。**

```text
s' = (cos + 1) / 2
```

   为什么？因为 TF-IDF 分数天然在 [0,1]，要融合就得先让两边“量纲一致”，否则权重 0.2 就没意义了。

### 4.5 数字例子

```text
query 向量 q = (1, 0)

候选A (1, 0)      -> cos = 1.0   （方向相同）
候选B (0.6, 0.8)  -> cos = 0.6   （部分相同）
候选C (0, 1)      -> cos = 0.0   （垂直，无关）
```

B 的计算：`(1*0.6 + 0*0.8) / (1 * 1.0) = 0.6`

## 5. 两者怎么融合（双路融合策略）

### 5.0 是不是双路融合？策略是什么？

**是双路融合。** 更准确地说，这是**分数级（late fusion）的线性加权融合**：

- **两路独立打分**（对同一批候选专家）：
  - 路 1：句向量语义余弦 —— 管“意思像不像”
  - 路 2：TF-IDF 关键词余弦 —— 管“术语对不对”
- **各自归一化到 [0,1]**，保证权重有意义；
- **逐候选线性加权**：`final = 0.8 × 语义 + 0.2 × 关键词`；
- **固定权重**（人工设定，不是学习出来的）；
- 最后再过阈值 + Top-K。

> 注意：这两路本质**都是余弦相似度**，只是向量空间不同（稠密句向量空间 vs 稀疏 TF-IDF 词空间）。

**融合层级对照（面试可提）**：

| 层级 | 做法 | 特点 |
|---|---|---|
| 早期融合 early fusion | 特征拼接后一起建模 | 需对齐特征、易受量纲影响 |
| 中期融合 mid fusion | 中间层交互 | 结构复杂 |
| **分数级融合 late fusion** | **各路独立打分再加权** | **简单、可解释、易调试（本项目）** |
| 排序融合 rank fusion | 合并排名（如 RRF） | 只看名次不看分值 |
| 学习式融合 | 用数据学权重/门控 | 上限高，但需标注数据 |

**为什么用分数级加权融合**：两路信号异构（稠密 embedding vs 稀疏词频），不适合直接拼特征；独立打分便于分别调试与解释；权重固定、实现简单、开销低。

**关键前提：先归一化到同一量纲。** 语义余弦在 `[-1,1]`，要 `(cos+1)/2` 映射到 `[0,1]`；TF-IDF 点乘天然在 `[0,1]`。不归一化，`0.8/0.2` 的权重就没有意义。

**只在专家匹配用了双路融合**：成果匹配是**单路（纯余弦）**，没有关键词路。

### 5.1 公式（纯文本）

```text
语义分映射: s_sem = (cos + 1) / 2         # 落到 [0,1]
关键词分:   s_kw  = TF-IDF 点乘           # 本来就在 [0,1]

最终分:     final = 0.8 * s_sem + 0.2 * s_kw
```

### 5.2 数字例子

| 专家 | 语义 cos | s_sem=(cos+1)/2 | s_kw | final = 0.8*s_sem + 0.2*s_kw |
|---|---:|---:|---:|---:|
| A | 0.90 | 0.950 | 1.00 | 0.8×0.950 + 0.2×1.00 = **0.960** |
| B | 0.60 | 0.800 | 0.31 | 0.8×0.800 + 0.2×0.31 = **0.702** |
| C | 0.10 | 0.550 | 0.00 | 0.8×0.550 + 0.2×0.00 = **0.440** |

阈值 `primary_threshold = 0.73`：

```text
A: 0.960 >= 0.73  -> 保留
B: 0.702 <  0.73  -> 过滤
C: 0.440 <  0.73  -> 过滤

最终只返回 A（若取 Top-3，也只返回满足阈值的 A）。
```

### 5.3 为什么要融合

```text
只靠关键词: 同义表达匹配不上（"智能质检" vs "视觉检测"）
只靠语义:   可能把"语义像但术语不对"的人选进来
融合:       语义管"意思通不通"，关键词管"术语对不对"，双重把关
```

## 6. 面试问答

**Q1：切词用什么？**
> jieba，具体是带词性标注的 jieba.posseg；只保留名词/动词/英文数字词，过滤停用词和单字词。jieba 自带词典，离线可用，不需要额外词表。

**Q2：需要数据库吗？**
> 不需要。数据用 pandas 从 Excel 读进内存，向量缓存成 .npy 文件，没有引入数据库。规模大了才会考虑关系库 + 向量库（FAISS/Milvus）。

**Q3：IDF 为什么能压通用词？**
> 通用词出现在几乎所有文档，df 大，IDF = ln(N/df) 就小；稀有术语 df 小，IDF 大。相乘后通用词权重被压低，术语被抬高。

**Q4：sklearn 的 IDF 和教科书一样吗？**
> 不完全一样。教科书是 ln(N/df)；sklearn 默认平滑成 ln((1+N)/(1+df)) + 1，并做 L2 归一化。

**Q5：为什么 TF-IDF 点乘能当余弦？**
> 因为 sklearn 默认 `norm='l2'`，每行已 L2 归一化，单位向量点乘就等于余弦。

**Q6：余弦为什么比欧氏距离适合文本？**
> 欧氏距离受向量长度影响，长/短文本会被误判；余弦只看方向，抵消了长度差异。

**Q7：为什么要 (cos+1)/2 映射？**
> 让语义分和关键词分都落在 [0,1] 同一量纲，加权才有意义。它不改变语义自身的排序，但会改变融合后的相对大小。

**Q8：0.8/0.2 和 0.73 阈值怎么来的？**
> 经验值，偏语义为主、关键词为辅。规范做法是在人工标注匹配集上网格搜索，用 Precision@K / Recall@K / MRR 评估，不能说成理论最优。

**Q9：min_df=2 有什么影响？**
> 过滤只出现一次的极稀有词，降噪降维；但可能丢掉一次性却很关键的技术名词，是精度/召回的权衡。

**Q10：还有哪些改进？**
> 用 BM25 替代 TF-IDF；Cross-Encoder 精排；把融合权重做成可学习；换更懂中文术语的领域 embedding。

## 附录 A. 多路融合方法全景与对比

> 先纠正一个常见误区：**“早期/中期/晚期融合”和“排序融合/学习式融合”不在同一条轴上。**
> - 轴一：**融合发生在哪里**（早期 / 中期 / 晚期）——经典多模态融合分类。
> - 轴二：**用什么方式合并**（加权 / 投票 / 排序 / 学习式 / 概率）。
> 本项目 = **晚期（分数级）融合** × **固定线性加权**。

### A.1 轴一：按“融合发生的层级”

| 层级 | 融合位置 | 做法 | 优点 | 缺点 | 典型场景 |
|---|---|---|---|---|---|
| 早期融合 early / feature-level | 输入特征层 | 把多路特征**拼接**成一个向量再建模 | 能捕获跨模态交互 | 需特征对齐、维度爆炸、量纲敏感、缺一路就难处理 | 图像+文本统一编码、特征工程 |
| 中期融合 mid / intermediate | 模型中间层 | 各路由各自的编码器，在**中间层交互**（cross-attention、gating） | 兼顾交互与解耦 | 结构复杂、训练成本高 | 多模态 Transformer、跨模态注意力 |
| 晚期融合 late / decision / score-level | 输出分数层 | 各路**独立打分**，再合并分数 | 模块解耦、可各自训练/替换、某路缺失仍可用 | 丢失路间细粒度交互 | **混合检索、集成、本项目** |

### A.2 轴二：按“怎么合并分数/结果”

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **线性加权** weighted sum | `final = Σ w_i * s_i`（本项目 `0.8/0.2`） | 简单、可解释、开销低 | 权重需人工定；各路必须先归一化 |
| 投票 voting | 多数票 / 平均 | 简单、抗单路异常 | 忽略分数强弱，只适合决策型 |
| 排序融合 rank fusion | 只看名次，如 **RRF** | 天然免疫分数量纲不一致 | 丢弃分数绝对值信息 |
| 学习式融合 learned | 用数据学权重 / 门控 / attention / MLP / MoE / stacking | 上限最高，能自适应 | 需标注数据，可能过拟合，可解释性差 |
| 概率/贝叶斯融合 | 融合各路的概率/似然 | 有统计解释 | 需概率校准 |

**RRF（Reciprocal Rank Fusion，混合检索常用）**：

```text
RRF_score(d) = Σ_r  1 / ( k + rank_r(d) )      通常 k = 60
```

- `rank_r(d)` 是文档 d 在第 r 个检索器里的名次（从 1 开始）。
- 只看名次、不看原始分值 → **天然解决“不同检索器分值不可比”的问题**。

其他常见变体：CombSUM（分数相加）、CombMNZ（分数和 × 命中路数）。

### A.3 相关但不同的：两阶段“召回 + 精排”

工程上还有一种常见组合，和融合经常一起出现：

```text
第一阶段 召回:  多路/单路向量检索，快速取 Top-N 候选（追求召回）
第二阶段 精排:  用 Cross-Encoder / 规则 对少量候选精细打分（追求精度）
```

它不算“融合层级”，而是**流水线架构**；两路召回的结果也可以用 A.2 的方式融合。

### A.4 对比总表

| 方法 | 复杂度 | 需要标注数据 | 可解释性 | 鲁棒性 | 捕获交互信息 | 典型用途 |
|---|---|---|---|---|---|---|
| 早期融合 | 中 | 中 | 中 | 低（缺模态差） | 高 | 多模态统一建模 |
| 中期融合 | 高 | 高 | 低 | 中 | 最高 | 跨模态 Transformer |
| 晚期 + 加权 | 低 | 否 | 高 | 高 | 低 | 混合检索、推荐、**本项目** |
| 晚期 + RRF | 低 | 否 | 中 | 高 | 低 | 多检索器融合 |
| 学习式融合 | 中高 | 是 | 低 | 中 | 中高 | 竞赛/大规模系统 |
| 两阶段召回+精排 | 中高 | 精排需数据 | 中 | 高 | 中 | 现代检索系统 |

### A.5 本项目定位与改进路线

- **定位**：晚期（分数级）融合 + 固定线性加权，`0.8 语义 + 0.2 关键词`，用于专家匹配。
- **为什么合适**：两路异构、无标注匹配集、追求简单可解释；晚期融合允许两路各自替换模型。
- **改进方向**（按投入排序）：
  1. 用人工标注匹配集**学习融合权重**（逻辑回归/小 MLP），替代固定 `0.8/0.2`；
  2. 引入 **RRF** 或 **门控融合**，让权重随 query 动态变化；
  3. 加 **Cross-Encoder 精排** 做第二阶段；
  4. 用 **BM25** 替代 TF-IDF 提升关键词路质量。

### A.6 面试问答

**Q：常见的融合方式是这几种吗？**
> 更准确说是两条轴。融合层级上经典的是早期/中期/晚期三类；合并方式上常见的是线性加权、投票、排序融合（RRF）、学习式融合。本项目属于“晚期融合 + 固定线性加权”。

**Q：为什么你们用晚期融合而不是早期拼接？**
> 两路一个是稠密句向量、一个是稀疏 TF-IDF，维度与量纲都不同，早期拼接还要对齐特征；晚期融合各自打分再加权，简单、可解释、任一路可独立替换。

**Q：线性加权和 RRF 的区别？**
> 线性加权用**分数**，要求各路先归一化到同一量纲；RRF 只用**名次**，天然免疫分数量纲不一致，但丢弃了分数强弱信息。

**Q：怎么把固定权重升级？**
> 用标注的匹配对训练一个融合器（逻辑回归/小 MLP/门控网络），输入两路分数、输出最终分，用 Precision@K / Recall@K / NDCG 评估。
