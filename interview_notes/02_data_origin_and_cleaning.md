## 1. 三张业务 Excel 最初从哪来（面试可用答案）

### 1.1 先记住：结论 + 证据 + 红线

**面试可直接说的版本**：

> 这三张表来自课题组合作的一个**企业技术创新 / 科技成果转化对接平台**的业务数据库，由平台方导出脱敏数据后提供。企业在平台注册时填写企业画像（名称、经营范围、行业分类、规模、注册资金等）；专家在平台注册或被推荐时填写研究方向与应用领域；科研成果和技术需求由高校、科研院所、企业在平台上发布。像企业规模 1/2/3 这种，就是平台注册表单里“规模”下拉框的选项编码。

**为什么可以这么说——字段证据（推断依据）**：

| 字段 | 含义 | 说明它来自什么系统 |
|---|---|---|
| `pub_dept` | 发布部门 | 有“发布”动作 → 供需发布平台 |
| `pub_status` / `pub_show_status` | 发布/展示状态 | 平台内容管理 |
| `dock_name` / `dock_name_tel` | 对接人/对接电话 | 技术对接业务 |
| `technical_broker` | 技术经纪人 | 成果转化平台专属角色 |
| `undertaker` | 承接方 | 技术转移业务 |
| `demand_status` | 需求状态 | 需求对接流程 |
| `collect_num` | 收藏数 | 平台内容指标 |
| `del_flag` / `create_by` / `update_by` / `create_time` | 删除标记/创建人/更新人/时间 | 典型后台管理系统的审计字段 |
| `biz_object_id` / `global_id` | 业务对象 ID / 全局 ID | 平台内部主键体系 |

这些命名集中出现在**技术供需对接 / 成果转化类**系统里，而不是单纯的工商登记数据。所以“成果转化/产学研对接平台”是**有证据支撑的推断**，不是凭空编的。

**红线（不要踩）**：
- 不要说“爬取自企查查 / 天眼查 / 知网 / 某政府平台”——一旦被追问接口、授权、合规、采集方式，立刻穿帮。
- 不要把“平台名”说死。可以说“课题组合作平台”，但不要编一个具体公司名。
- 数据确实是课题组给的 → 就说脱敏导出；如果连这个都不确定 → **先问导师**。

### 1.2 需要向导师确认的问题清单

1. 三张表来自哪个平台/项目？是自建系统还是第三方平台？
2. 数据是导出脱敏，还是爬取？有无数据使用授权？
3. 大概的覆盖范围（多少家企业、多少专家/成果）和时间范围？
4. 企业规模等字段是平台注册时由企业自己填，还是平台/审核方录入？

> 这四个问题确认清楚，数据来源这一块就彻底稳了。

## 2. 怎么“知道”数据有这些问题？（方法论）

关键认知：**脏数据不是猜出来的，是看出来的。** 写清洗规则前，先做**数据探查（data profiling）**。

### 2.1 数据探查通常看什么

| 检查项 | 具体做法 | 能发现什么问题 |
|---|---|---|
| 表结构 | 看列名、列数、dtype | 哪些列明显与任务无关（`id`、`logo_url`）、哪些是敏感字段（`linkman_email`） |
| 缺失率 | 每列非空比例 | 哪些字段大量为空、是否要整行删除 |
| 重复 | 按业务主键（`org_name`、`title`）统计重复 | 重复企业、重复成果 |
| 取值分布 | `value_counts` 低基数列 | `scale` 只有 1/2/3 → 是编码不是文本 |
| 唯一值 | `nunique` | `research_field` 出现“学”这种无意义单字 |
| 文本抽样 | 随机抽几行长文本字段肉眼看 | 工商模板、`〓`、换行、HTML、括号免责声明 |
| 格式一致性 | 抽查日期/币值/标点 | 时间带时分秒、行业字段末尾带标点 |
| 正则扫描 | 匹配 `<...>`、`&nbsp;`、`["..."]`、`\n` | HTML 标签、HTML 实体、类 JSON 字符串、控制字符 |

### 2.2 举个真实过程的例子

比如企业表：

1. 打开列名 → 发现几百列，大量是 `create_by`、`total_score` 这类系统字段 → 决定删列。
2. `df['scale'].value_counts()` → 只有 `1/2/3` → 判断是编码 → 需要映射成“小型/中型/大型”。
3. 随机抽 5 条 `business` → 看到“一般经营项目是：”“〓”“（依法须经批准……）\n” → 写规则清理。
4. `df['org_name'].duplicated().sum()` → 有重复 → 按名称去重。
5. 扫 `category` 末尾 → 有“；”“。”残留 → 写规则去尾标点。

**所以面试这样说**：

> 我不是先想好一堆规则，而是先做数据探查：看列结构、缺失率、重复度、取值分布和文本抽样，把发现的问题按“结构层、记录层、字段层”分类，再针对每一类写规则。规则是由数据样例驱动的。

## 3. 一张表有那么多不同的问题，怎么分别清洗？

### 3.1 清洗的固定顺序（很重要）

清洗不能乱序，否则后面要返工。推荐顺序：

```text
第 1 步 删列      ：去掉无关列、敏感列、状态列          （结构层）
第 2 步 行级清洗  ：去重、删空行、删明显异常行          （记录层）
第 3 步 字段级清洗：对每个保留字段做标准化              （字段层）
第 4 步 全局收尾  ：去首尾标点、统一空值、统一编码      （收尾）
```

### 3.2 为什么按“列”为单位写函数

不同字段的语义不同，清洗方式也不同。所以**一列一个清洗函数**，互不干扰：

| 字段 | 专属清洗逻辑 | 为什么这么洗 |
|---|---|---|
| `scale` | `1→小型 2→中型 3→大型` | 编码转语义，方便模型理解 |
| `establish_time` | 只保留 `YYYY-MM-DD` | 时分秒对画像无意义 |
| `company_org_type` | 删括号及之后内容 | “有限责任公司（自然人投资）”→“有限责任公司” |
| `business` | 删工商模板、乱码、控制字符、括号免责声明 | 只留真正的经营范围 |
| `category*` | 去尾标点、删纯数字行 | 行业字段要干净 |
| `application` | 只把**引号外**逗号改分号 | 引号内逗号属于同一描述，不能动 |
| `research_field` | 删序号、删项目符号、统一分隔符 | 便于后续切分和匹配 |
| `title` | 删“成果：/需求：/寻找”前缀、按标题去重 | 统一可比 |

> 面试点：**清洗规则是由该字段的下游用途决定的**。比如 `application` 要拿去匹配，就必须保证“一个描述项不被错误拆开”，所以才要区分引号内外。

### 3.3 清洗后怎么验证

| 验证维度 | 做法 |
|---|---|
| 规模 | 清洗前后行数、列数 |
| 完整性 | 关键字段非空率 |
| 唯一性 | 重复率 |
| 合理性 | 文本长度分布、异常短/超长样本 |
| 正确性 | **随机抽样人工比对**原始值与清洗结果 |

> 面试必答句：**不能以“脚本跑完没报错”当作清洗正确**，必须抽样核对。

### 3.4 这套清洗的局限（主动说出来加分）

- 规则是**人工手写**的，不是自动化的，新增数据源要重新适配。
- 正则比较激进，可能误伤（如删括号会连带删技术限定，删序号可能影响“3D 打印”）。
- 缺少数据版本管理，理想做法是“原始层 / 清洗层”都保留，可回溯。

## 4. 专家数据到底是什么？从哪来？

### 4.1 是什么

**专家 = 科研人员/技术人员的档案卡。** 关键字段：
- `user_name` 姓名
- `research_field` 研究方向
- `application` 应用领域（更贴近落地场景）
- `duty` 职务、`professional_title` 职称、`college` 单位
- `btype_name` 类别

他们是**外部科研供给方，不是这家企业的员工**。

### 4.2 从哪来（可证明 + 推断）

- **可证明**：仓库里是 `experts_full.xlsx`，字段含注册/展示痕迹。
- **推断**：来自同一个成果转化平台——专家在平台注册或由平台/高校推荐后录入，`btype_name`（如“高校专家”）、`college`、`professional_title` 都指向“科研人员库”。

### 4.3 有什么用

系统用**企业的经营范围**去**匹配专家**，把匹配到的专家的 `application` 当作 **“研究趋势”** 塞进 prompt。所以专家数据的作用是：**提供“学术界/科研界在做什么”的信号**。

---

## 5. 科研成果数据到底是什么？从哪来？

### 5.1 是什么

**成果 = 可以转化、对接的技术成果条目。** 关键字段：
- `title` 成果名称
- `analyse_contect` 成果分析/介绍
- `application` 应用领域
- `main_function` 主要功能、`main_advantage` 主要优势
- `scene_lable` / `chain_lable` 场景/产业链标签

**注意：成果不是这家企业自己的**，是一个**独立的外部成果库**。prompt 里明确写了“（非企业自身的、外部的成果）”。

### 5.2 从哪来（可证明 + 推断）

- **可证明**：`needs_achievements_full.xlsx` 里 `contect_type=1` 的部分，由 `split_needs_achievements.py` 拆出。
- **推断**：来自平台成果发布——高校、科研院所、企业把成果发布到平台，形成成果库。

### 5.3 有什么用

按**企业画像与成果文本的相似度**，给企业匹配 Top-K 外部成果，作为“可以借鉴/转化的具体技术抓手”提供给大模型。

## 6. 企业需求数据是什么？有啥用？

### 6.1 是什么

**需求 = 企业发布的技术难题/技术需求**（“我需要某种技术”）。字段：
- `title` 需求标题（常带“寻找/寻求”前缀）
- `analyse_contect` 需求描述
- `application` 应用领域
- `pub_dept` 发布部门

原始与成果同表，`contect_type=2` 的部分由拆分脚本拆出。

### 6.2 从哪来（推断）

企业在平台上发布的技术需求，由平台运营审核后展示，所以有 `pub_dept`、`demand_status` 这类字段。

### 6.3 有啥用

- 平台核心业务：**需求 ↔ 成果 / 需求 ↔ 专家** 的技术对接。
- 在本项目的当前版本：需求数据**没有进入 SFT 主链路**（主链路输入是 企业 + 专家方向 + 成果）。

**面试口径**：
> 需求数据完成了独立清洗，是平台“技术对接”业务的另一半，为后续“需求—成果匹配、需求—专家匹配”做准备；当前创新方向生成版本主要使用企业画像、匹配研究方向与科研成果。

> 不要把需求说成“当前已参与模型训练”。

## 7. 外部学术数据（arXiv）怎么获取、怎么检索、怎么用

**对应代码**：`arxiv_process/arxiv_scraper.py`

### 7.1 怎么获取（检索方式）

用 Python 的 `arxiv` 库按关键词检索：

```python
arxiv.Search(
    query=<关键词>,
    max_results=per_page,       # 每页默认 100
    sort_by=arxiv.SortCriterion.Relevance,   # 按相关性
)
client.results(search)
```

- 关键词通过命令行 `--query` 传入，年份用 `--year-start/--year-end` 过滤。
- 分页通过 `--pages` 控制；每页之间 `sleep(1)`，每篇论文之间 `sleep(3)`，避免触发 API 限流。
- 每个分类代码再通过 arXiv 官方分类表（`arxiv.org/category_taxonomy`）翻译成人类可读名称，并缓存到 `arxiv_categories.json`。

### 7.2 抓了哪些字段

```text
arxiv_id, title, authors, abstract, doi, categories, pub, citations, journal_level
```

### 7.3 期刊和引用量怎么补：NASA ADS → OpenAlex → Crossref

这是**一条“依次尝试、失败就降级”的兜底链**，目的是回答两个问题：**这篇论文发在哪个期刊（`pub`）？被引用了多少次（`citations`）？**

```text
第 1 优先：NASA ADS API        get_ads_info(arxiv_id)
             ↓ 没拿到 pub
第 2 优先：OpenAlex API        get_openalex_info(doi, arxiv_id)
             ↓ 还没拿到
第 3 优先：Crossref API        get_crossref_info(doi)
```

三个数据源的作用：

| 来源 | 用什么查 | 返回什么 |
|---|---|---|
| NASA ADS | `identifier:arXiv:<id>` | 期刊/发表信息、引用数 |
| OpenAlex | `works/doi:<doi>` 或 `works/arxiv:<id>` | 发表venue、`cited_by_count` |
| Crossref | `works/<doi>` | 期刊名、`is-referenced-by-count` |

**为什么用多个？** 因为覆盖率不同：有的论文在 ADS 有、在 OpenAlex 没有，反之亦然。依次尝试能尽量把空缺补上。

### 7.4 期刊等级怎么算

拿到期刊名后，用本地映射表查等级：

```text
CAS 中科院分区  +  JCR 分区  +  CCF 会议/期刊等级
→ 拼成 journal_level（多个用 ; 连接，查不到为“未找到”）
```

### 7.5 怎么用（必须诚实）

**当前状态：arXiv 数据没有接入 SFT 主链路。** 主链路的研究趋势来自专家 `application`。arXiv 是一个已开发的**外部学术数据补充模块**。

面试口径：
> 项目开发了 arXiv 抓取与期刊等级映射模块，用于补充论文级别的外部学术信息（发表 venue、引用量、CCF/CAS/JCR 等级），可作为后续研究趋势信号和成果质量评估的数据源；当前创新方向生成的训练主链路主要使用企业画像、匹配专家方向和科研成果。

> 不要声称“研究趋势来自 arXiv 抓取”，这与代码不符。

## 8. 发现的真实技术债（面试加分项）

面试官若问“代码有没有问题”，可以主动指出（体现你真的读过代码）：

1. **arXiv 兜底链的 Crossref 分支实际是死代码。**
   ```python
   pub, cites = get_ads_info(aid)
   if pub is None and (aid or doi):        # aid 恒为真 → 条件等价于 pub is None
       pub, cites = get_openalex_info(doi, aid)
   elif pub is None and doi:               # 只有上一个 if 为假才会到这里，而那时 pub 不为 None
       pub, cites = get_crossref_info(doi) # → 永远走不到
   ```
   正确写法应是两个独立的 `if` 依次降级，而不是 `if/elif`。

2. **`get_openalex_info` 使用了 OpenAlex 已废弃的 `host_venue` 字段**，新版本应改用 `primary_location.source.display_name`。

3. **`arxiv_scraper.py` 在导入阶段就要求 `ADS_TOKEN`**，没有 token 直接 `RuntimeError`，不利于没有 ADS 账号的人运行。

## 9. 高频追问与参考回答

**Q1：数据是爬的还是官方给的？**
> 核心企业/专家/成果/需求数据是课题组合作平台导出的脱敏数据；外部论文数据是官方 API（arXiv + ADS/OpenAlex/Crossref）获取的。两者合规路径不同：前者依赖数据授权，后者依赖 API 使用条款。

**Q2：你怎么知道数据脏？**
> 通过数据探查：列结构、缺失率、重复度、取值分布、文本抽样和正则扫描。问题是被数据样例“看出来的”，不是猜的。

**Q3：清洗规则冲突或误伤怎么办？**
> 规则按列隔离、按固定顺序执行，减少相互影响；对激进规则（如删括号）保留原始字段以便回溯，并通过抽样人工复核控制误伤。

**Q4：专家和成果怎么保证匹配对？**
> 用向量相似度 + 阈值 + Top-K；专家还叠加 TF-IDF 关键词分。阈值是经验值，规范做法要用标注集调参（详见匹配篇）。

**Q5：需求数据为什么不用？**
> 需求是平台“技术对接”业务的另一半，当前生成任务聚焦“企业→研发方向”，所以先不引入；后续可做需求—成果匹配。

**Q6：arXiv 数据到底用没用？**
> 模块已开发，但当前未接入训练主链路；研究趋势用的是专家应用方向。arXiv 定位是后续的外部趋势信号与质量评估数据源。
